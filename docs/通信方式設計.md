# OFFLINE_TALK 通信方式・初期アーキテクチャ決定

更新日: 2026-11-04
状態: 採用候補（iPhone実機での成立性確認が完了するまで距離・品質は未保証）

## 実装状況（2026-11-04）

- iOS試作に親機・子機のBonjour発見と接続、チャンネル選択を追加済み。
- PTT用の発言権制御と、入力サンプルレートから16 kHzモノラルPCM16へ変換して送る音声中継を追加済み。
- 可能な場合のVoice Processingと、受信再生キューが300 msを超えた場合に古い音声を破棄する上限を追加済み。
- 接続ごとに送信を直列化し、未送信音声は最大8チャンクまで保持して古いチャンクを破棄する処理を追加済み。
- 発言権を保持して送信を続ける連続送話モードを追加済み（同時送話は一台）。
- 子機名の親機表示、切断表示、前面表示中の子機による親機再検索・自動再接続を追加済み。
- アプリが前面から外れた場合にPTT・連続送話を解放する処理を追加済み。端末名から制御文字を除去。
- バックグラウンド中の切断・再接続をローカル通知で知らせる処理を追加済み（通知許可時）。
- 画面上に現在の発言者名を表示。
- XcodeコンパイルとiPhone実機確認は未実施。現在のPCM方式は暫定で、遅延、音質、通信詰まり、サンプルレート、5台接続時の性能を評価していない。
- 音声バックグラウンドモードを設定済みだが、画面ロック中の継続は未実機検証。PTT操作と自動再接続は前面表示中を対象とする。
- 連続送話モードは実装済みだが、5台利用、音質、遅延、長時間のバッファ動作は未確認。

## 目的

インターネット、携帯電話回線、Wi-Fiルーターなしで、近くのiPhone同士が音声通話する。初期対象はiPhone X (iOS 16.7.11) と iPhone 15。Androidは後続段階。

## 判断

### 通信媒体

Wi-Fi無線を端末間のデータリンクとして使い、AppleのピアツーピアWi-Fiを有効化したNetwork frameworkを第一候補とする。これはWi-Fiルーターやインターネットを介さずApple端末間のネットワーク接続を作れる。通常のWi-Fiインフラや携帯回線への接続は通信要件に含めない。Wi-Fi無線自体はオンにする必要がある。

Multipeer ConnectivityはiOS 16では利用でき、旧APIの人数枠は今回の5台を上回る。ただしAppleは2026年に同フレームワークを非推奨とし、Network frameworkを案内しているため、新規開発の本命にはしない。Network frameworkの従来API（NWBrowser / NWListener / NWConnection）をiOS 16互換の実装候補とする。

AppleのピアツーピアWi-Fiの通信方式は公開されておらず、Apple端末向けである。Androidとの直接互換性はない。Android対応時には別の共通通信方式を設計・検証する。

### 通信トポロジー

親機を1台選び、子機が親機に直接接続するスター型とする。親機は子機の音声を他の参加者に中継し、接続一覧と発言権を管理する。目標は親機1台と子機最大4台の計5台。

親機が停止・圏外になった場合の親機移譲は初期段階では対象外とし、親機復帰または全員の再参加を検討する。

### 音声と利用モード

試作にはPTT方式と、発言権を保持して送話を続ける連続送話モードを実装済み。どちらも親機が送話権を管理し、一度に一人だけが送話する。マイク形式、音声遅延、混信、エコー、長時間動作は未測定であり、実装済みでも実用性は未確認。

音声は小さなリアルタイムチャンクに分けて転送する。実装時にAppleの音声API、iOS 16で使えるコーデック、バッファ長を比較する。送話は親機が管理し、一度に一人だけが話すハーフデュプレックスを初期仕様候補とする。

### チャンネル

1〜10は無線周波数ではなく、アプリ内の論理グループ番号とする。親機は選択チャンネルの参加者のみを同じセッションへ入れる。チャンネル選択は電波干渉を分離しない。

### 初期ワイヤープロトコル

TCPストリーム上に4バイトのビッグエンディアン長さヘッダーを置き、その後に1バイトのメッセージ種別とペイロードを続ける。受信側はTCPの受信境界に依存せず、長さヘッダーに従って完全なメッセージを組み立てる。

- メッセージ種別: 発言権要求、許可、拒否、解放、送話開始、送話終了、音声、端末名通知。
- 音声ペイロード: 16 kHz、モノラル、符号付き16ビットPCM、リトルエンディアン。
- 音声ペイロード上限: 4096バイト。空または奇数バイトの音声メッセージは接続を終了する。
- チャンネル番号はBonjourサービス名で照合する。暗号化、認証、端末ID照合はまだ実装していない。

この形式は初期PoC用で、Androidとの相互接続仕様として確定したものではない。Android対応前に端末名の文字コード、認証、暗号化、フレーム上限、切断時の送話権解放を共通仕様として定める。

## 対応OSとAPI制約

- 最低対応OSはiOS 16。全APIにiOS 16での利用可否を確認し、新しいOS専用APIには代替処理を用意する。
- iOS 26以降のAPIだけを使ってiOS 16対応を損なわない。新しい資料にあるNetwork frameworkの新APIはそのまま導入せず、NWBrowser / NWListener / NWConnection等の既存APIを調査する。
- 接続、音声、画面ロック、アプリ切替、システムによる中断は別々に検証する。iOSのバックグラウンド実行は無制限ではないため、ロック中・強制終了後の常時待受や自動再接続を保証しない。
- 通話中のバックグラウンド音声を実装する場合は、Audio Sessionとバックグラウンドモードの要件を満たし、ユーザーが明示的に通話を開始・終了する設計にする。

## 距離と品質の扱い

10〜100mはユーザーの目標範囲だが、Appleは本用途の保証距離を示していない。壁、人、端末の向き、電波混雑、親機の位置などで変化する。まず近距離で音声を成立させ、屋外の見通し距離を段階的に測る。100mが必須条件なら、スマートフォン単体方式の試験結果を見てから専用中継器・無線機器の要否を判断する。

## 段階的な検証計画

1. **接続PoC:** iPhone XとiPhone 15で、ルーター・インターネット・携帯回線を使わず発見、参加、切断を確認。
2. **2台音声PoC:** PTTで双方向の音声を送り、遅延、途切れ、エコー、発熱、電池消費を確認。
3. **5台スター接続:** 親機1台・子機4台で参加者表示、チャンネル分離、発言権、切断通知、再接続を確認。
4. **距離測定:** 同じ部屋から開始し、屋外で10m、30m、50m、100mの見通し条件を複数回測る。距離ごとに接続維持と音声品質を記録。
5. **利用状態:** 画面ロック、アプリ切替、着信・音声中断、親機の離脱、アプリ強制終了を個別に試す。
6. **常時通話:** PTTの結果が安定してから追加し、同時発話を禁止するか、優先順位を設けるかを検証する。

## 次の開発単位

まず2台の接続・PTT音声PoCを作り、iPhone X (iOS 16.7.11) とiPhone 15で実測する。実機ビルドにはXcodeが必要なため、このWindows環境では編集を行い、ビルド・署名はクラウドMac等で行う。TestFlightを使う場合、配布時にはインターネットとApple Developer Programの準備が必要。インストール後の通信試験は端末同士を近くに置き、オフラインで行う。
